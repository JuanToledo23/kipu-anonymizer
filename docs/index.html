Sell the data without selling the people

Systems design · Juan Toledo · 31 Oct 2026

Stack: Python 3.13 · FastAPI · SQLite · Docker · Fly.io · OpenRouter (Claude + Gemini)

What we solve. Kipu Pay wants to sell its support chats, documents and tables to train a chatbot. We deliver the same information with every real person swapped for an invented identity that is believable and consistent. No leaks, no rewriting of the text, and no pseudonym changes when new data arrives.

How we deliver it. An HTTP service that regenerates the output and anonymizes new records live. The who-is-who dictionary never leaves the server.

Design principle: AI proposes; code decides, executes and verifies.

Architecture — the pipeline in 7 modules

1

Ingestion code

httpxPyMuPDF (PDF)lxml (HTML/XML)csv Latin-1Pydantic

Downloads chats, documents and tables from the API and reads them in full, including metadata, comments and file names.

Why it exists: personal data also hides in the corners.

How: an API client downloads each source; one reader per format converts everything to the same record schema (id, text, metadata, attachments) and keeps a raw copy on disk.

2

Person directory code

PythonSQLite

Builds the list of who exists from the master tables and Slack, and gives each person a fixed internal id.

Why it exists: the tables say who is who with certainty; the text only allows guessing.

How: reads clients, employees and Slack users; creates one person per row with all their identifiers and their direct manager; assigns an internal id that is stored in SQLite.

↓
3

Detector codeAI

regexcustom validatorsOpenRouter: Claude + Geminijson_schema

Finds every piece of personal data: rules for anything with a format, AI for names in free text. Only what appears verbatim is accepted.

Why it exists: rules alone miss names; AI alone invents and over-redacts.

How: the rules run first over each text; then the text goes to the AI models, which return the exact mentions they found; the code checks that each mention exists verbatim and drops anything on the keep list.

↓
4

Identity codeAI

union-find (Python)SQLiteClaude (adjudicator)

Decides which person each mention belongs to using strong evidence; AI only breaks ties, and the code verifies its evidence.

Why it exists: merging two people into one, or splitting one into two, breaks the dataset.

How: a mention joins a person if it shares a strong identifier; if only the name matches, it stays apart; in ambiguous cases an AI model picks among candidates, citing evidence that the code checks.

↓
5

Pseudonyms codeAI

HMAC-SHA256Colombian name listsSQLite UNIQUEClaude (gender/sector)

Generates a fake, believable and deterministic identity for each person, and stores it in an on-disk registry.

Why it exists: the same person must get the same pseudonym today, live, and tomorrow.

How: a seed is derived from the internal id and a secret; with it, name, national id (cédula), email, mobile number and address are picked from our own lists and generators; they are reserved in SQLite so they stay unique and stable.

↓
6

Replacement and generalization codeAI

Pythonunicodedata

Replaces only the detected fragments, preserving their form, and generalizes whatever identifies someone without naming them.

Why it exists: the value is in the original text; rewriting it alters it.

How: each mention is replaced by its pseudonym at the exact position, copying the original form (capitals, missing accents); occupation, neighborhood and year are swapped for their general version.

↓
7

Independent auditor codeAI

regexunicodedata + confusableshashlibClaude (final pass)

Searches the whole output for every original value; if it finds a leak, it reprocesses that record and audits again until there are none.

Why it exists: a single leak invalidates the dataset; nothing ships without verification.

How: normalizes the whole output and searches for each original value and its hashes; an AI pass looks for people the rules did not know about; any finding goes back to the detector; at the end it builds the dictionary from what it actually found.
